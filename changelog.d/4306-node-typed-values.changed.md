- A clinical or party node row now stores only the part of its canonical JSON fragment that its own columns do not hold: `_type`, a lowercase `archetype_node_id`, a plain or simply coded name, and an ELEMENT value in one of the common basic shapes (a quantity, count, ordinal, coded or plain text, date, time, duration, identifier, boolean or URI) move into columns, the value into the new typed value columns. Every reader rebuilds the omitted keys, so the canonical JSON and every AQL result are unchanged, and a filter on a quantity's magnitude or a code reads its column directly. The node heap shrinks by about a third (storage generation 3); a row written before keeps its whole fragment and reads the same. Migrations `ext/0005`, `clinical/0019` and `party/0012` add the columns and the readers; no data is migrated.
