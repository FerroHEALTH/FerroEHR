- An AQL query ordered by `c/uid/value` with a `LIMIT` no longer starts a parallel worker on every call, and no longer switches between that plan and a sort of the whole join depending on the planner statistics. The version uid it sorts on had no index, so the planner sorted the version rows through a parallel `Gather Merge`, which costs a worker's start-up per query on a server of any size: about 19 ms on the storage bench's CI runner, where the two flat-shape path reads measured 23 ms in some rounds and 42 ms in others. Migrations `clinical/0024` and `party/0015` add an index on the uid expression of the hot version partition, so the query reads versions in uid order from it in one backend and stops at the limit.
