- The viewer draws every page on its server with FerroUI 0.6, with no Leptos and no WebAssembly: a link and a form load a new page, and FerroUI's own small script modules add behaviour on top of what the server drew, so every page works with JavaScript off. The image ships the one `ferroehr-viewer` binary, with no `/site` tree beside it and no `hash.txt`; FerroUI's stylesheet, theme and scripts are served from inside it under `/ferrohealth-ui/0.6.0/`, and `/pkg/` no longer answers. The Content-Security-Policy is now `script-src 'self'; style-src 'self'` with no per-response nonce and no `'wasm-unsafe-eval'`. The image no longer reads `LEPTOS_SITE_ROOT`, `LEPTOS_OUTPUT_NAME` or `LEPTOS_HASH_FILES`, so a deployment that sets them can drop them; `LEPTOS_SITE_ADDR` naming another address than `server.listen` still refuses the start. A proxy rule written for `/pkg/` (the hosted deployment's `Cache-Control` for it is removed) has nothing left to match.
