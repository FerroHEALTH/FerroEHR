- The viewer runs on `ferrohealth-server` 0.4.2 and takes its Content-Security-Policy from the family's server-rendered console headers (FerroHEALTH/FerroSYS#202) in place of a layer of its own. The policy a deployment sees is unchanged: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`, with no nonce. FerroUI's assets under `/ferrohealth-ui/` keep the `Cache-Control` FerroUI sets, and a refusal under that path is `no-store` whatever FerroUI's router sets, so a cache in front of the viewer keeps no error answer for an asset. The REST server takes the same `ferrohealth-server` release with no change in what it serves.
