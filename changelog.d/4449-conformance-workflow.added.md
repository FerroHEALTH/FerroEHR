- The Conformance workflow runs the Veredictum 0.3.0 catalogue in CI through the Veredictum GitHub Action, pinned by commit SHA and running the release image by digest. It builds FerroEHR from the commit, composes it with FerroTERM beside it on fresh volumes, reviews the party statement with `veredictum validate`, fails on a failed or errored row, writes the Markdown summary to the job summary and uploads the results, JUnit and CTRF views. It runs on pull requests that touch the server, the party set, the conformance compose files or the workflow, on `main`, on a release tag and twice a week. `scripts/conformance.sh` takes a stage (`run`, `review`, `up`, `down`), so CI and a local run compose the same deployment, and `scripts/checks/veredictum-action.sh` fails while the Action SHA, its version comment, the image digest and `VEREDICTUM_VERSION` disagree.
