- An AQL query aimed at named EHRs (the ITS-REST `ehr_id` parameter) reads those EHRs' objects first and each object's own content after them, whatever the planner statistics say. When an archetype's rows fell out of the most-common-value list of the archetype statistics, the planner estimated them at one row and could start from that archetype over the whole population, evaluating every projected path for every EHR's rows before the EHR filter: the storage bench's wide projection over one EHR read about 10 000 pages per call in some rounds and 1 200 in others. A node contained in a versioned object is now read inside its parent on such a query; results do not change.
