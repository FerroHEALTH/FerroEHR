- The conformance pipeline runs Veredictum 0.3.1. The Conformance workflow drives the catalogue through the Veredictum Action twice, each run on fresh volumes: under the `released` profile, the frozen openEHR release, which is the record and decides the job, and under the `development` profile, the pinned `master` of each openEHR repository, which is published beside it under its own job summary heading and artifact and never counted toward it. Both runs include the SMART documents: the Action now takes the SMART Platform base URL and the committed test issuer's key. The workflow reads the result paths and the exit status from the Action's outputs. `scripts/conformance.sh` takes the profile as `CONF_PROFILE` (`released` by default; a `development` run writes to `docs/conformance/ferroehr-development/`) and drives the SMART documents in the same run, and the IXIT carries the test issuer's `scoped_tokens` declaration.
