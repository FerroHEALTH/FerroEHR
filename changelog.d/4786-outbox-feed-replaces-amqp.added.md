- The commit-event outbox feed. `[outbox] readers` names the readers (`FERROEHR__OUTBOX__READERS`); boot registers each one and marks every reader the list no longer names inactive, so it holds the retention prune back no longer (#4766). `GET /admin/outbox/{reader}?limit=&domain=` answers the PHI-free envelopes after the reader's cursor in `seq` order, and `POST /admin/outbox/{reader}/ack` with `{"last_seq": n}` moves the cursor (`204`; `409` below the cursor or past the highest row; `404` for an unknown or inactive reader). Both routes need the `__ferroehr.outbox` scope, every read is an access record, and the clinical and party outboxes each keep their own `seq` and cursor. A read waits for a commit that drew a lower `seq` to end, so a reader never acknowledges past a row that becomes visible later. The prune now counts from the commit instant and keeps every row an active reader has not acknowledged (migrations `clinical/0030_outbox_feed.sql`, `party/0023_outbox_feed.sql`). With no reader named, no commit writes an outbox row.
