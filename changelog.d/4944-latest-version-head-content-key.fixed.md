- A `LATEST_VERSION` AQL read of an object whose versions share one node tree reads that tree once again. Since a version identical to its predecessor reads its predecessor's node rows, a read could reach a shared row through every version of a long identical chain before keeping the head: the storage bench's two-leaf path read fourteen times the pages. `vo_head.trunk_head_content_key` now names the head's node rows and every `LATEST_VERSION` read joins on it, and the `version` partitions declare a `vo_id` distinct count (`n_distinct = -0.5`) so the planner never prices a probe of one object's versions at one row (migrations `clinical/0034`, `party/0026`). The storage generation moves to `generation-6` (`ext/0012`).
