- The one `PERSON` mapping SCIM provisioning, just-in-time creation and the login binding share: `[[authz.party_binding.person.template]]` with the binding key, `userName` and `externalId` selectors of each template, `[[authz.party_binding.person.attribute]]` with the SCIM attribute, the OpenID Connect claim and the path of each mapped value, and `[authz.party_binding.professional_role]`, `[authz.party_binding.group]`, `[authz.party_binding.membership]` and `[authz.party_binding.representation]`. Boot refuses a mapping that breaks one of its rules, naming the key, including a template that is absent, rooted at another class or lacks a mapped path, and deleting a template the mapping names is refused with `409`.
- The new party migration `0028_binding_selectors` holds each binding key, `userName` (compared after RFC 8265 width mapping, lower case and NFC), `externalId` and group `displayName` to one live party, so a commit giving one a second party is refused with `409`. The first boot fills the side table under the mapping's digest, a replica with another mapping refuses to start, and `ferroehr party-binding refill` rebuilds it after a mapping change, refusing while a replica runs and naming the parties when a value is carried twice.
- `POST /admin/party/binding-key` re-keys a `PERSON`'s binding key: it refuses the administrator's own login and a key already bound, retires the old key in the same commit and writes one access record carrying both.
