- A MyHealth@EU contact point's caller (a `contact_point = true` `federation` issuer) reaches patient data only for the patient of its treatment relationship confirmation. The token's `ehdsi.patient.id` (`system|value`) is resolved to its EHR through the EHR index, and every patient-data request must name that EHR. A token without it is refused with `403` and `ERROR_SEC_DATA_INTEGRITY_NOT_ENSURED`, recorded as `refused-trc-missing`. Another patient's EHR, an unknown EHR and a request naming no EHR all answer one `404` of the new problem type `trc-patient-mismatch`, carrying the agreement service's `*_NOT_FOUND` code and recorded as a `refused-trc-patient-mismatch` security event (eHDSI XCA Profile 8.0.1 §4.2.1, §4.2.2). A contact point's person agreement now names its `ehdsi_service`; upgrade step: set it, and list the issuer in `[smart] patient_issuers`.
- An external person under an agreement with `discard` discards a dispensation of a listed template, as a logical delete, within `discard_window_hours` and from the same point of care: the dispensation's `health_care_facility` carries the token's provider identifier and its eHDSI `organization-id`. A token carrying permissions records and discards a dispensation only with `PPD-046` (eHDSI SAML Profile 10.0.0 §2.5).
