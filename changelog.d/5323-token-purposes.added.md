- The access record takes the purposes of use and the professional roles from the access token. An issuer with an `[[auth.attributes]]` table states them through the IHE IUA `purpose_of_use` and `subject_role` claims (IHE ITI TF-2 §3.71.4.2.2.1.1) or the `purpose_of_use` of RFC 9396 `authorization_details`. The new `token_attributes` column of the audit store holds them, a new record is chain digest version 3, and the EHDS access record and the BALP `AuditEvent` write them with their code systems. A request whose `[audit] purpose_header` names a purpose the token does not state is refused with `403`, and the refusal is recorded. The header alone keeps working for an issuer without the table.
