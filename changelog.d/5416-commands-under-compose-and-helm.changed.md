- The book's command-line page shows how to run `ferroehr config check`, `party-binding check` and `party-binding adopt` in each place FerroEHR runs. On a host you call the binary. Under Docker, `docker run … config check` checks a mounted file before an upgrade, `docker compose run --rm --no-deps ferroehr config check` checks the configuration of a service that refuses to start, and `docker compose exec` runs the database commands. Under the Helm chart, `kubectl exec deploy/<release>-ferroehr -c ferroehr` runs them, and a one-off pod copied from a failing pod runs `config check` on a configuration the server refuses. The party-binding migration page links each of its steps to these forms. Each example was run against the 5.7.0 image and chart 25.0.1.
