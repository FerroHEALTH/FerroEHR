- **Breaking: the SMART discovery document describes exactly one issuer, never a `machines` issuer and never by table order.** With `[auth.smart] discovery = true`, 5.7.0 described the first issuer whose metadata it read, whatever its kind, so in the quickstart with the Keycloak overlay the document sent user launches to the `machines` SCIM issuer, which signs no user token (SMART App Launch 2.2.0, Conformance, §Metadata: `authorization_endpoint` is where a launch starts). The document now describes the issuer the new key `[auth.smart] described_issuer` names, else the one issuer that is not of kind `machines` and whose metadata FerroEHR has (read from it, introspected, or supplied by `issuer_metadata_file`). Naming a `machines`, unknown or metadata-less issuer refuses the start. Without the key, more than one such issuer refuses the start, naming them and the key, and none refuses it, saying no issuer can be described. Upgrade step: set `described_issuer` when you run more than one user-facing issuer (`persons`, `patients` or `federation`) with discovery on (#5425).
