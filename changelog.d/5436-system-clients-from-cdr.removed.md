- **Breaking: `[[authz.system_client]]` is removed from `ferroehr.toml`**, with every key it held (`issuer`, `client_id`, `provider`, `facilities`, `writes`, `origins`, `device_identifier_issuers`); a configuration that still sets it refuses boot as an unknown key. A system client is now granted in the CDR: an `AGENT` (or any `ACTOR`) carrying its `client_id`, acting for its provider `ORGANISATION` by an acts-for relationship (or, with none, for the deployment's `[authz.party_binding] provider`), and performing a `ROLE` whose capability grants `commit_composition` with its templates, facilities, origin (`relay` or `device`) and device identifier issuers, each read by its `ferroehr-operations` code; a change applies on the next request with no restart. The Helm chart 31.0.0 drops `config.authz.system_client` (a major bump: a values file that sets it is refused), and the Keycloak quickstart grants its service client `commit_composition` beside `query_system_wide` through the Demographic API. See the book's "Operational policy" page.
- The example `ROLE` `openEHR-DEMOGRAPHIC-ROLE.data_migration.v1` is removed (#5432): a migration is a system client whose `ROLE` grants the import and export operations, on the system client example `ROLE`, which now names each credentials element by its `ferroehr-operations` code.
