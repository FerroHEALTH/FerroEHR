- **Breaking: the client lists `ferrohealth-smart` read while it classifies a token are policy the CDR holds**, read on every request with no restart. `[[auth.issuer]] first_party_clients`, `[[auth.issuer.delegates]]` (with `client`, `sub` and `issuer`) and `[[auth.scopeless_subjects]]` (with `issuer` and `sub`) are removed, and a file or `FERROEHR__AUTH__*` variable that sets one is refused as an unknown key. The server answers the crate's standing questions from the grants of the `ACTOR` carrying the client identifier under the token's issuer, through three new operations of `ferroehr-operations`: `sign_in_persons` (a client persons sign in through), `act_for_persons` (a client, or the RFC 8693 actor a person's token names, that acts for a person) and `access_without_scope` (a system caller admitted to every SMART on openEHR requirement without a resource scope). `[authz.grants] allowed` admits each by name, and its default admits none. The answer comes from the copy of the grant rows each replica holds, so a token adds no database transaction, and a party store that cannot answer refuses the token with `503`. To move a deployment, write the client's `AGENT` and a `ROLE` coding the operation through the Demographic API (or `ferroehr party-binding grant`), and list the operation in `[authz.grants] allowed`. The Helm chart 32.0.0 drops `first_party_clients` from its example values (a major bump), and the Keycloak quickstart grants its viewer `sign_in_persons`. `ferrohealth-smart` moves to 0.24, `ferrohealth-authz` to 0.17, `ferrohealth-session` to 0.19, `ihe-atna` and `ehds-logging` to 0.18, `ihe-iti` to 0.9 and `ferrobridge-term` to 0.10.
