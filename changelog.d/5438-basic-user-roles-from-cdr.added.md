- A Basic user bound to a `PERSON` holds the roles and SMART scopes its policy grants name, beside its `[[auth.basic.users]]` table: the new `ferroehr-operations` codes `hold_roles` and `hold_scopes` grant what the capability's `role` and `scope` elements name, under `[authz.grants] allowed`. A change through the Demographic API applies to the user's next request with no restart. A token's roles and scopes still come from the token alone.
- A policy grant is the second source of the privileged permissions beside `[authz.rbac] role_issuers`: an `import_ehr` or `import_ehr_extract` grant admits the matching import with no `import_role`, and a `read_identifiers` grant admits `GET /admin/party/identifiers` with no `identifier_reader_role`, each under `[authz.grants] allowed`. A `hold_roles` grant naming `admin_role`, `emergency_access_role`, `import_role` or `identifier_reader_role` is refused at commit with `403` and never honoured. See the book's "Operational policy" page, "Which checks read a grant".
