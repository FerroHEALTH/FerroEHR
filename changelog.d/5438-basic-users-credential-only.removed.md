- **Breaking: a Basic user is a credential alone.** `[[auth.basic.users]] roles` and `scopes` are removed, and a file that sets either is refused as an unknown key. A Basic user bound to a `PERSON` holds the roles and SMART scopes the `hold_roles` and `hold_scopes` grants of its `PERSON` name, never a privileged role. The one trust key added, `[authz.rbac] first_admin` (`FERROEHR__AUTHZ__RBAC__FIRST_ADMIN`), names the Basic user that holds `admin_role` and `[auth] product_scope` from the configuration: the first administrator, who writes the first policy parties; a name that is no Basic user refuses the start. `ferroehr party-binding grant --basic-user <user>` grants an operation to the `PERSON` a Basic user binds to, on the operator's authority. The quickstart, the hosted sandbox, the development lanes and the performance gate make their Basic user the first administrator and grant its scopes and roles this way (`scripts/scim-provision.sh` does it for the lanes it provisions), and the development configuration no longer declares `import_role`. The Helm chart 32.0.0 drops `roles` and `scopes` from its Basic users.
