- The party mapping defaults to FerroEHR's default demographic definitions. Each boot stores the seven definitions of `deploy/definitions/` whose id the definition store does not hold, as it stores the policy definitions, and never overwrites a stored one. With no mapping key set, `[authz.party_binding]` `person`, `professional_role`, `group`, `membership`, `representation` and the new `patient` section map them, so an empty configuration boots with SCIM Users, Groups and representation working. A section a deployment sets replaces that section's default, and nothing is stored under a deployment's own ids. A SCIM client whose `[[auth.party]]` table sets no `group_identifier_issuer` writes its Groups' `externalId`s under its `binding_issuer` with `/groups` appended, where the start was refused before. The quickstart (both its EHR index variants), the hosted sandbox, the development, conformance, performance and viewer lanes and the Helm chart drop the mapping keys that restated the default and their `ferroehr definitions load` step, and the chart's `definitions.files` is empty by default (chart 26.2.0). A deployment that maps its own templates keeps its keys and its definition list.
