- A party that ever had a policy version is now hidden from a caller without `[authz.rbac] admin_role` on both read paths, every version of it. Demographic AQL judged each version on its own, so it served the ordinary versions of a party an administrator had turned from a policy party into an ordinary one, while the Demographic API refused them. The commit that stores a policy version now marks the party in the same transaction, nothing clears the mark, and the party migration marks the parties already stored; an import, an archive load and `ferroehr party-binding refill` mark from the stored versions. The Demographic API read and write rules and demographic AQL all key on that one mark, which AQL reads from the head row each query already joins, so no statement is added.
