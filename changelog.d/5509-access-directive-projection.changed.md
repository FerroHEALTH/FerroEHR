- The commit of an `EHR_ACCESS` version writes the EHR's settings, one row per directive and exception and one row per sensitivity label into side tables in the same transaction (clinical migration 0038), and notifies every replica, which drops its copy of the EHR's settings. A revoked gate-keeper or directive now decides the next request on every replica; the few-second expiry of the settings index, which could leave a revoked setting in force on another replica, is gone. A replica whose listener is down reads the settings on every request, and a settings store that cannot answer is `503` (it was `500`). The first boot fills the side tables from the stored versions, and `ferroehr party-binding refill` rebuilds them. No configuration key is added or removed.
