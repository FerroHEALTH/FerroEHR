- **Breaking: four role names are removed from `[authz.rbac]`:** `subject_audit_role`, `access_service_roles`, `import_role` and `identifier_reader_role`. A configuration that still sets one refuses boot as an unknown key. Each permission is now a grant in the CDR and nothing else, under `[authz.grants] allowed`: `read_subject_audit` reads the access log of one subject (`GET /fhir/r4/AuditEvent` with one `patient`), `access_service` makes a caller an EHDS Art. 10 access service held to an opt-out, `import_ehr` and `import_ehr_extract` admit the matching import, and `read_identifiers` admits `GET /admin/party/identifiers` beside the admin role. A role a token or a Basic user names grants none of them. Recording an access opt-out is refused with `400` while `[authz.grants] allowed` does not allow `access_service`. `[authz.rbac] role_issuers` now governs `admin_role` and `emergency_access_role` alone, and the development compose configuration drops `import_role`. See the book's "Operational policy" page, "What the grants decide".
