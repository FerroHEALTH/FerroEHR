- **Group memberships of a provider for the access evaluator.** A `PARTY_RELATIONSHIP` in an `ORGANISATION`'s `relationships` carrying `ferroehr-operations::member_of` makes that provider a member of the target `GROUP`, read by its code in any archetype. A system client acting for the `ORGANISATION` acts for the `GROUP` too, so a consent permit naming a regional `GROUP`, such as one copied from the region's IHE BPPC opt-in policy, admits it in a read and a query. Every replica holds the memberships beside the other caller facts, so a request reads them with no transaction of its own. Only a caller holding `write_care_relationship`, or an administrator, changes an `ORGANISATION`'s memberships; anyone else gets `403`. An `ORGANISATION` carrying `under_care_of` is still refused `422`.
