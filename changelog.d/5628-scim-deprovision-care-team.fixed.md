- A SCIM client deactivates, reactivates and deletes a professional who belongs to a care team without the `write_care_relationship` grant, where both were refused `403`. The care check compares what each care relationship of the new version says with the last version that holds a body, so a lifecycle state or a logical deletion changes none. A deactivation keeps every care relationship and drops only plain Group memberships, a reactivated User holds its care relationships as before, and the login is refused on its next request on every replica (`refused-inactive`, `refused-deprovisioned`). The ADT system still ends or changes a deactivated professional's care relationships: its version keeps the `inactive` state, so it can no longer reactivate the login, and a version that asks for another state is refused `403`.
