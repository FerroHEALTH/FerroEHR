- FerroEHR applies the merges, unmerges, links and unlinks of an IHE PMIR Patient Identity Registry such as FerroPIX. A new `[pix]` table (`endpoint`, `feed_issuer`, `feed_client_id`, and `[[pix.identifier_domain]]` naming the `DV_IDENTIFIER` type a linked identifier of each domain is written with) subscribes with ITI-94 and receives ITI-93 messages on `POST {public_base_url}/pmir/feed`, admitting only the configured client's access token. Each message is stored before it is acknowledged, and an unmerge or unlink stops the split identifiers and record subjects resolving on every instance from receipt. One instance applies the messages in arrival order, each as one demographic contribution committed as the Registry's client and recorded in the access log as `pmir-message:<id>`; a redelivery changes nothing, and a message that does not state what it does is refused and kept split. Migration `party/0047` adds `pmir_message`, `pmir_identity`, `pmir_merge`, `pmir_suppression` and `pmir_subscription`. The Registry's client needs the `write_care_relationship` grant.
