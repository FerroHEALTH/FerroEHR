- The access log seals each append in one signed checkpoint, written in the append's own transaction, instead of signing every link. Every committed entry is covered by a signature from the moment it commits, whichever replica wrote it, and a population query that reaches twenty EHRs costs one signature instead of twenty. The link signatures are gone: `audit.access_log_record.signature`, `audit.access_log_chain_gap.signature` and `audit.access_log_chain_reserve()` are dropped, the checkpoint is stored by its columns, and a checkpoint must name the link the log holds at its position (migration `audit/0036`). The checkpoints and link signatures written before it are dropped; the first append after it seals the chain below. The scheduled five-minute checkpoint of the access log is gone, since every append seals itself; the system chain keeps its schedule. A run of expired tombstones now folds whole, and the checkpoints inside it leave with it. `ferroehr access-log checkpoint` and `POST /admin/access-log/checkpoint` answer the checkpoint of the head and seal one only for a head appended without a key. No law this release reads requires a signature per entry; the eHDSI Audit Trail Profile's per-event signature binds national contact points.
