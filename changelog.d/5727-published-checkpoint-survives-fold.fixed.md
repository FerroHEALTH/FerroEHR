- A checkpoint published outside the database now keeps verifying after retention folds the run of tombstones it sealed. The publication marks each checkpoint it writes (`audit.access_log_checkpoint.published_at`), and the fold keeps a published checkpoint inside the run and records in the gap (`seals`) the position, the link it sealed and the SHA-256 of its proof, so `ferroehr access-log verify --checkpoint <file>` and `POST /admin/access-log/verify` check an old published checkpoint through the gap. An unpublished checkpoint inside a run still leaves with it.
