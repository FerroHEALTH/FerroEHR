- The access evaluator checks the access policy's `purpose_required` as step 4, before the controller's rules: a request without a purpose under a policy that requires one is refused `403 refused-purpose-missing` whatever rules the policy holds. A controller rule's `purposes` now match only a purpose the request declares, so a rule such as "no medical examination" no longer refuses a request that declares no purpose; set `purpose_required` to refuse those. A subject's deny directive over a purpose still covers a request without one. The controller rules are step 5, sensitivity step 6 and the care relationship step 7, in the access record's step names as well.
