- The access log's chain head is held only for what needs it (#5745). Requests write their records into an append-only intake (`audit.access_log_intake`, `audit.audit_event_intake`; migration `audit/0041`), so no request waits on the head. A chainer on every replica links the intake into the chains. It takes the head without waiting, so one replica chains at a time, computes the links in Rust and writes the records with every column the server supplied. The insert trigger checks each link and no longer derives the columns; the verifier still derives and compares them. syslog now delivers from the store (`audit.syslog_outbox`) as the FHIR Feed does, so neither feed holds a record in memory. New metrics `access_log_chain_hold_duration_seconds` and `audit_chained_total`; `access_log_entries_total` and `access_log_append_duration_seconds` now count and time a request's intake write. The `audit_sender` readiness indicator reads `DEGRADED` when the oldest intake record has waited more than 10 seconds.
