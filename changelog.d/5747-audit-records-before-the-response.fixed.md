- Access records are no longer dropped under load or lost when the server stops or crashes (#5747). Every audit record of a request, the access-log entry of an access to EHR data included, is written into the audit store in one transaction before the response leaves. A request whose records cannot be written is refused with `503 Service Unavailable` and `Retry-After: 1`. Under load this is back-pressure, never silent loss: at 2000 mix requests per second the old in-memory queue dropped 40 % of the records. The same holds for the records the service writes itself (subject resolutions, EHR-Extract transfers, the access-log erasure, the access-policy write), and a server whose audit subsystem does not start now refuses to boot. See the book's "Audit trail" page, "How a record is written".
