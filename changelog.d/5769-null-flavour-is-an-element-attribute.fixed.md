- A Web Template no longer presents an ELEMENT's `null_flavour` constraint as a value alternative. RM data structures §ELEMENT makes `null_flavour` an attribute beside `value`, and ITS-REST simplified formats master05 §ELEMENT addresses it as `/_null_flavour`. The builder turned the constraint into a `coded_text_value` child at `…/null_flavour`, so an ELEMENT with one value type was not promoted (`…/boolean` was refused and `…/boolean/boolean_value` expected), a FLAT or STRUCTURED read showed a stored null flavour a second time as a coded value, and a write to that key stored a null flavour. The ELEMENT now promotes to its one value, the null flavour reads and writes only as `…/_null_flavour`, and the template's list of null flavour codes is still enforced on commit. In `openehr-sdt`.
