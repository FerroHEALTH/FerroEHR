- Each instance keeps the lookups of the login binding and the names of the bound `PERSON`s in memory, so a request whose caller it holds makes no party-store statement to resolve it, where it made two. A change of a key row, a membership, a representation or a key space drops every lookup, and a new version of a `PERSON` drops its name, on every instance through the new `ferroehr_party_binding` notification channel (party migration 0050); the instance whose commit made the change drops its copy before it answers, so a deprovisioned login is refused on its next request. While the channel's listener is down every request reads the store, as before. Each instance now holds six listener connections, two of them on the party database, and the `policy_listeners` health indicator names the new `party_binding` listener.
