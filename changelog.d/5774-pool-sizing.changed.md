- Each domain pool is sized for the instance and opened before the server answers ready. `[database] max_connections` unset (the new default, where it was 20) is four per core the server may run on, at least 10 and at most 30, and never above `server.max_concurrent_requests`; `[database] min_connections` unset (where it was 2) keeps one connection per core open, at least 2, and the server opens them before it answers ready, so an instance restarted under load no longer refuses its first requests while it connects. A request now gives its connections back when its handler has answered, so the audit record and the response's way out hold none, and the new `db_pool_hold_duration_seconds` histogram shows how long a request holds each. The book's configuration reference gives the sizing rule. The Helm chart (36.0.0) no longer sets `config.database.min_connections: 0`. Upgrade: a deployment of more than one instance on one PostgreSQL sets `max_connections` per instance, as the book's connection budget under Running several instances computes.
