- A deployment that trusts only `machines` issuers serves the SMART Backend Services discovery document for its one `machines` issuer: the token endpoint, the client credentials grant, `private_key_jwt` and the `system/` scopes, with no `authorization_endpoint` and no launch capability (SMART App Launch 2.2.0, Backend Services, Retrieve `.well-known/smart-configuration`). FerroEHR takes `ferrohealth-smart` 0.28, whose shared `describe` rule now describes such a deployment and returns the purpose with the issuer; the server builds the document under that purpose instead of an app-launch document from a `machines` issuer.
