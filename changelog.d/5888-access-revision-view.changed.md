- The access revision a read selects beside its own columns comes from the view `access_revision_of` in a scalar subquery of the same statement (migrations `clinical/0052` and `party/0053`). The function `access_revision(ehr)` it replaces was never inlined by PostgreSQL, so every head, version, EHR and settings read ran one extra statement per row. The stale-copy check of an AQL query pinned to one EHR compares the revision inside the query and raises `ZA001` through `access_stale_copy()` as before, which replaces `access_in_force`. A single-EHR AQL request runs three fewer nested statements. No configuration key was added or removed.
