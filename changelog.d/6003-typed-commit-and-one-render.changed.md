- A COMPOSITION commit no longer builds a canonical JSON value of the body. The server validates, scans, offloads and signs the typed COMPOSITION, then renders it once: `version.body`, the content digest, the node rows, the feeder origins and the blob references all come from that one rendering. A commit in canonical JSON now makes 10 representation changes where it made 673. `version.body`, the content digest and the RFC 8785 signed form are unchanged, held equal over every corpus COMPOSITION. A `553|incomplete|` commit still validates over a canonical value.
- A COMPOSITION whose large `DV_MULTIMEDIA` the server offloads to the blob store now has the members of each offloaded value in model order (`uri`, `data`, …, `integrity_check`, `integrity_check_algorithm`, `size`) in `version.body`, as every other value has. Before, the members the offload adds came last. The JSON value and the signature are unchanged, but the content digest of such a body changes once, so an identical re-send of a version stored before this release is committed again instead of being answered with the stored version.
- The EHR read serves the RM `EHR` rendered straight to JSON or XML, and a party read serves the stored body verbatim for JSON and reads it straight into the RM type for XML, with no canonical value in between. Responses are unchanged.
