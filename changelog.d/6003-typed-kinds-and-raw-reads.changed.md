- An `EHR_STATUS`, `EHR_ACCESS` or FOLDER commit, on the EHR create, the `EHR_STATUS` update and the directory routes, no longer builds a canonical JSON value of the body: the server validates and offloads the typed object and renders it once. `version.body`, the content digest and the RFC 8785 signed form are unchanged, held equal over every corpus document of each versioned kind.
- A CONTRIBUTION member is read once into its RM type and validated over it, where it was validated over its canonical value. The member is still stored and signed as the JSON its client sent. A CONTRIBUTION of the 128 KB IPS composition now makes 16 representation changes where it made 675, with about a third fewer allocations.
- The COMPOSITION read at an instant, the `EHR_STATUS` and `EHR_ACCESS` reads, the directory reads and the `PARTY_RELATIONSHIP` read serve the stored body verbatim for JSON and read it straight into the RM type for XML. `VERSIONED_COMPOSITION` and `VERSIONED_EHR_STATUS` are rendered straight from their RM type. A COMPOSITION read at an instant now allocates about 92% less.
