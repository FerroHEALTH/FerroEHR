- An AQL query no longer builds its result cells as jsonb in PostgreSQL. The statement returns the stored columns of each node row a projected path reads, and the server rebuilds the fragment, evaluates the path and writes each cell once, straight into the `RESULT_SET` body (#6004). Cell contents are unchanged. `SELECT DISTINCT` and a projected list of attestations still build their cells in SQL, where PostgreSQL compares or aggregates them.
- The `RESULT_SET` `ETag` is now the SHA-256 of the response bytes as written, leaving out only the per-response `meta._created` stamp, so every served `ETag` value changes once with this release. It still stays the same for an unchanged result set and changes with its rows or its executed query (#6004).
