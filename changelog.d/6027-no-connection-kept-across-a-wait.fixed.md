- A server under more load than its pools serve no longer stops for ten seconds at a time. A request whose access decision reads the party store beside the request's own clinical read kept the connection of whichever read finished first while the other still waited for its pool. Once every connection of both pools was kept so, each request waited for a connection only another waiting request could give back, PostgreSQL sat idle, and every other request was refused with `503` until the acquire timeout. A request now keeps no connection while it waits for a pool, for a copy another request is loading or for a lock another holds. `db_pool_nested_acquires_total{order="kept_while_waiting"}` counts a request that does, and stays at 0.
