- A CONTRIBUTION whose body writes a member name twice in one JSON object is refused `400`, in the envelope, in an audit and inside a member's `data`, on `POST /ehr/{ehr_id}/contribution` in canonical JSON, FLAT and STRUCTURED and on `POST /demographic/contribution`. The direct commit routes already refused it; the CONTRIBUTION routes read such a body through a parsed value, which kept the last occurrence and committed it. An object with a repeated name is ambiguous (RFC 8259 §4) and has no canonical form (RFC 8785 §3.1), so a client that sent one has to send each member once.
