- **An AQL query can be narrowed to the caller's caseload.** The JSON body of `POST /query/aql` and of a stored query's `POST` execution takes the FerroEHR extension members `caseload` (`direct`, `team`, `all`, `none`) and `caseload_roles` (role codes, `terminology::code` or a bare code). The caseload is the EHRs whose subjects the caller holds a live care relationship to by that path and in those roles, with the policy's grace and for a provider the caller acts for, never on a self-declared relationship. It only narrows: the access decision still applies to every row. It is a condition of the query's one SQL statement, so `COUNT`, `LIMIT` and paging see only the narrowed rows. An unknown value, roles without a caseload, a policy whose `caseload` is `false`, a purpose outside the policy's `care_purposes` and a demographic query are refused `400` naming the member. The care projection now carries each relationship's role (clinical migration `0060_access_care_role`), and it is rebuilt once after the upgrade.
