- The draft access control package specifies care relationships with a role, a provider and cover, read through the closed paths `direct`, `team`, `self_declared` and `attested` and stored one by one; the scheme `confidentiality`, whose `CONFIDENTIALITY_SETTINGS` is now the parent of `ACCESS_DIRECTIVE_SETTINGS`, with a record's marking `N`, `R` or `V` and the controller's exclusions; and the controller's facts about care relationships and representation in `ACCESS_POLICY`. The generated draft model carries every new class and attribute, and the server refuses a settings or policy version that sets one no access decision reads yet, naming it, instead of storing what it would not enforce.
- Breaking: the HL7 code systems of the access terminology are named `HL7_` plus the code system's name, so `consent-provision-type` is `HL7_ConsentProvisionType`, `extra-security-role-type` is `HL7_SecurityRoleType`, `v3-RoleClass` is `HL7_RoleClass` and `audit-event-action` is `HL7_AuditEventAction`. Settings, policies, memberships and access-log filters written with the former identifiers are refused or match nothing; the default care-team definitions and the book use the new ones.
