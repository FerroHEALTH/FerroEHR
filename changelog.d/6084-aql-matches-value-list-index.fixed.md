- An AQL `matches` over a list of strings now reads through the same index as `=` on the same path. Before, it read every node of the queried class and tested each value. A `WHERE p/details/items[at0001]/items[at0010]/value/value matches {'1950-01-01', '1950-01-02'}` on `PERSON` took as long as a scan of all persons, while the same path under `=` took under a millisecond; now both forms take the index. This holds for text leaves of an `ELEMENT` value (`value/value`, `value/id`, `value/units`, `value/symbol/value`) and for codes (`value/defining_code/code_string`, also after a `TERMINOLOGY('expand')`), for literals and string parameters. A list with a member that looks like a number on `value/value`, or with a number literal, reads as before, as `=` with that member does. The answers are unchanged.
