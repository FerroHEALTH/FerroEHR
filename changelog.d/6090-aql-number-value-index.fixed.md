- An AQL equality on an ELEMENT value's `value/value` with a text that reads as a number (`= '19500101'`, or `matches {'19500101', '1950-01-01'}`) now enters through an index on the number of a `DV_ORDINAL` or `DV_SCALE` value, instead of reading every node of the archetype. The answers are unchanged. The new index adds 72 bytes of write-ahead log per ordinal or scale value a commit writes, and nothing to a commit without one. The migrations `ext/0016`, `clinical/0057` and `party/0060` create the function and the index and analyze `node_hot`; on a large store the index build takes its time at upgrade.
