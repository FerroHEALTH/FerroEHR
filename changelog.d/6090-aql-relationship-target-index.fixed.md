- A demographic AQL query filtered on a party's relationship target (`WHERE p/relationships/target/id/value = '<party id>'`, or `matches` over a list of party ids) now reads the parties whose current version names that target from the reverse-relationship index, instead of reading every party of the class. The answers are unchanged: the comparison still holds the exact text, and a query over `ALL_VERSIONS` or a version predicate reads as before.
