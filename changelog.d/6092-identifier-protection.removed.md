- **The national-identifier protection is removed.** A national identifier belongs in the master patient index (FerroPIX, over IHE PIX/PDQ and PIXm), and the CDR holds the subject only as a pseudonym. The server no longer seals an identifier out of a party body: a party is stored, digested, signed and served as committed. Gone with it: `[privacy.identifier_protection]` (`schemes`, `key`, `key_file`), the national-identifier scheme registry and its codes, the root key and its subkeys, the audited read `GET /ferroehr/rest/extensions/v1/admin/party/identifiers` and its `read_identifiers` grant operation, the sealed rows in the admin dump archive, and the import and load refusals of a plaintext or foreign protected value. Migration `party/0059_drop_national_identifier.sql` drops the tables `national_identifier` and `identifier_scheme`. A configuration that still sets the section, in the file or as `FERROEHR__PRIVACY__IDENTIFIER_PROTECTION__*`, is refused at boot naming the key. Encryption at rest of the database volumes and backups is now a documented deployment requirement on the go-live checklist. The care projection no longer needs the key: it digests subject references with SHA-256 and runs on every deployment, and migration `clinical/0056_access_care_unkeyed.sql` resets it so the first run rebuilds it.
