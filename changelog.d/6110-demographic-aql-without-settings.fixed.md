- An AQL query rooted at a demographic class no longer answers `503` when the EHR access settings store is unavailable. The server judged the request's per-EHR access condition before it planned the query, although a demographic query never applies it. The condition is now judged only for a query that reads EHR data, so a demographic query reads no access settings and depends only on the reads it makes; a clinical query still answers `503` while the settings cannot be read.
