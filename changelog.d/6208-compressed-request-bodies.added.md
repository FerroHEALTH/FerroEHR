- A request body can be sent compressed. With `Content-Encoding: gzip` (or `x-gzip`) or `br` the server decodes it before any route reads it, so a compressed commit stores the same version as the uncompressed one; an IPS composition commit of 128,474 bytes is 8,483 bytes in gzip. Any other coding is answered `415` with `Accept-Encoding: gzip, br`, a body that decodes past `server.body_limit` or `api.body_limit` is answered `413` without decoding the rest, and one that does not decode `400`. The new `server.request_decompression` key, on in FerroEHR's defaults, turns it off. FerroEHR moves to ferrohealth-server 0.12.0 and the performance gate to ferrohealth-perf 0.15.0.
