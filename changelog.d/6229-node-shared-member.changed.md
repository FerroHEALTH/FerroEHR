- A member repeated across the node rows of one version is stored once: the first row that carries it keeps it, and a later row whose member is byte-identical and at least 128 bytes leaves it out and names that row in the new `node.shared` column. An IPS composition commit, whose entries repeat one participation list, writes 42,545 bytes less write-ahead log (18.8 %). Every reader puts the member back with one probe of the node key, so canonical bodies, digests and AQL results are unchanged; a query that filters or projects a shared member reads that extra row (an `other_participations` predicate over 1,000 IPS EHRs went from 116 to 168 ms). The members an index reads from the row itself (`value`, `time`, `origin`) are never shared. The v6 baseline migrations change in place.
