- A population AQL query with a value filter that it also projects, such as cdr-benchmark's `bp_data_filtered` (`SELECT …/magnitude … WHERE …/magnitude >= 140 ORDER BY … DESC`), no longer runs into the request timeout on a store that fills from empty before autovacuum first analyses it. With no statistics PostgreSQL estimated both the archetype's OBSERVATIONs and the filter's index rows at one row, and walked the archetype index once per filtered row: 30 M buffers for 2,400 compositions. Every statement with a value filter an index serves now reads its contained nodes inside their composition, so the filter's index is its one entry from the population, as it already was when only the WHERE clause read the filtered value. The rows a query answers do not change.
