- A write's access-log entry (a COMPOSITION commit, update or delete, a CONTRIBUTION, an `EHR_STATUS` commit) no longer sends the database a shared part the store already holds, and names its search tokens by id, as a read's entry does: about 6 kB less to the database per write, and four fewer statements run inside it. The stored entries are unchanged. If the store no longer holds such a part, or the token ids are of an older generation, the write sends the entry again in full, so an admitted access is still recorded once, durable before the write is visible.
