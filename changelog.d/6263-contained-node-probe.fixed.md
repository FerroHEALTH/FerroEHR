- A population AQL query whose value filter sits only in the WHERE clause no longer runs into the statement timeout on a store that has grown since its last `ANALYZE`. On such a store the planner estimated the contained OBSERVATION at one row and rescanned it, with the WHERE clause's `EXISTS`, once per matching version: 32.7 M buffers for 500 rows. When the WHERE clause filters on a leaf that the SELECT does not read, each node a CONTAINS step finds is now read inside its own object, as a query scoped to named EHRs already does. The rows a query answers do not change.
