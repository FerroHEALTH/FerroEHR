- An access to EHR data no longer renders the BALP `AuditEvent` of its access-log entry on the request. The audit task's frontier round, about once a second, renders each new entry from the stored entry and stores its ITI-81 search tokens on the entry's row in `audit.access_log_index`; `audit.access_log_entry` keeps no `search_tokens` column, and the write of an entry resolves no token. An ITI-81 search on `address` or a token parameter first moves the index past every entry written before it, so it still finds an entry written a moment ago; when an open database transaction keeps the index from catching up within 2 seconds, the search answers `503` with `Retry-After: 1` and is never left hanging. An entry costs 134 fewer allocations on the request (145 instead of 279) and writes about 40 fewer bytes of write-ahead log (775 instead of 815 on a composition read).
