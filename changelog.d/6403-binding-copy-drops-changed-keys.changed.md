- A party write drops from each replica's binding copy only the lookups it changed, where it dropped every lookup and name. The commit of a transaction that changes the binding side table notifies its binding revision and its change set (the parties of the rows it wrote, the key of each key row, the issuer of each other identifier row), and each replica drops the lookups the set names and holds the others at the new revision. A set out of order, too large for one notification or naming a key space's state drops every lookup. A PERSON create, update and delete and a ROLE create send two round trips fewer to the party store, which no longer reads the caller's binding again.
