- **Breaking: draft access settings and the access policy answer `422` for content that breaks a rule.** `EHR_ACCESS.settings` and `PUT /admin/access_policy` answered `400` for a body that reads but breaks an invariant of the draft access control model or another rule, where every other write answers `422` (RFC 9110 §15.5.21; the ITS-REST `422` response is content that "could be converted to a resource, but there are semantic validation errors"). They now answer `400` only for a body that does not read as the class (another scheme, an undeclared member, no canonical-JSON `ACCESS_POLICY`) and `422` for a broken invariant, a code outside its terminology, a controller that is not the policy's, an unknown time zone, and an `opt_out` directive while `[authz.grants] allowed` does not allow `access_service`. The served OpenAPI document lists the `422` on the admin access policy and EHR_ACCESS routes.
