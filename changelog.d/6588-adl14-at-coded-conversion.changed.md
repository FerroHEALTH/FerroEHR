- `GET /definition/archetype/adl1.4/{archetype_id}/adl2` and `GET /definition/template/adl1.4/{template_id}/adl2` now answer at-coded ADL 2.4 (`adl_version=2.4.0`). The conversion keeps every ADL 1.4 node and value code as written, where it renumbered them into id-codes before, so a composition recorded with the ADL 1.4 at-codes commits under an ADL 2 template built over the converted archetypes (ADL 2 preface, Backward Compatibility). This is a breaking change for a client that reads the id-codes. `openehr-adl` converts to at-coded ADL 2.4 by default, and `ConvertConfig::coding` selects id-coded ADL 2.
- An ADL 1.4 archetype parsed by `openehr-adl` now carries the full version its `revision` item states as its identifier, so `ArchetypeRepository` resolves a pre-release such as `openEHR-EHR-EVALUATION.device_summary.v0.0.1-alpha` by its full identifier, which `create_opt` and the server's template upload both need.
