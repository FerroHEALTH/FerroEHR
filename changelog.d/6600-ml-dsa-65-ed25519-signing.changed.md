- **Breaking: `pgp` mode signs with ML-DSA-65+Ed25519, the post-quantum composite of RFC 9980 (algorithm ID 30), and refuses a classical signing key at boot.** Version signatures, access-log checkpoints and system-log seals are version 6 OpenPGP signatures (RFC 9580) over SHA2-512 that carry an Ed25519 and a hedged ML-DSA-65 signature, both computed in `aws-lc-rs` through the family crate `ferrohealth-openpgp-pq` and both required to verify (RFC 9980 §3.2). A signature over a hash with a digest under 256 bits (RFC 9980 §5.3.1), or over MD5, SHA-1 or RIPEMD-160 (RFC 9580 §9.5), is refused before any cryptography. An Ed25519, EdDSA or RSA key in `record.signing.key_file` stops the start with an error naming the key, unless the new `[record.signing] allow_classical_key = true`, which signs with it and warns at boot that high-risk use must complete the move by 31.12.2030; ECDSA and Ed448 keys stay refused. Signatures already stored keep verifying against the configured and retired certificates. Upgrade step: generate an ML-DSA-65+Ed25519 key with `ferrohealth-sop generate-key --signing-only` (`cargo install ferrohealth-openpgp-pq --version =0.1.0 --locked`), point `key_file` at it, and list the old certificate's public half in `retired_key_files`; or set `allow_classical_key = true` to keep the classical key for now. The documentation cites RFC 9580 in place of RFC 4880, which it obsoletes (#6600).
