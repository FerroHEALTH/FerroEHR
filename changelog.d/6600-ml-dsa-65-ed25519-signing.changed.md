- **Breaking: `pgp` mode signs with ML-DSA-65+Ed25519, the post-quantum composite of RFC 9980 (algorithm ID 30), and refuses every classical signing key at boot.** Version signatures, access-log checkpoints and system-log seals are version 6 OpenPGP signatures (RFC 9580) over SHA2-512 that carry an Ed25519 and a hedged ML-DSA-65 signature, both computed in `aws-lc-rs` through the family crate `ferrohealth-openpgp-pq` and both required to verify (RFC 9980 §3.2). A signature over a hash with a digest under 256 bits (RFC 9980 §5.3.1), or over MD5, SHA-1 or RIPEMD-160 (RFC 9580 §9.5), is refused before any cryptography. An Ed25519, EdDSA, RSA, ECDSA or Ed448 key in `record.signing.key_file` stops the start with an error naming its fingerprint. The signatures releases 3.0 to 5.7 stored keep verifying against the configured and retired certificates, subkeys included. Upgrade step: generate an ML-DSA-65+Ed25519 key with `ferrohealth-sop generate-key --signing-only` (`cargo install ferrohealth-openpgp-pq --version =0.1.0 --locked`), point `key_file` at it, and list the old certificate's public half in `retired_key_files`. The documentation cites RFC 9580 in place of RFC 4880, which it obsoletes (#6600).
