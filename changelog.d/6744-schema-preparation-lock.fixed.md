- Replicas that start together against an empty database no longer race each other. Two servers creating the schemas at once failed with `duplicate key value violates unique constraint "pg_namespace_nspname_index"` and the loser restarted; on Kubernetes one of the chart's two default replicas restarted on most fresh installs. The whole schema preparation of a database now holds one PostgreSQL advisory lock, so the later replicas wait and find every migration applied.
