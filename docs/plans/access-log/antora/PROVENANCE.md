# Provenance: the draft access log specification, in the openEHR Antora layout

This tree is the draft openEHR specification change of the access log
design (`docs/plans/access-log.md`), laid out to drop into the openEHR RM
specification repository as a new Antora module. It is FerroEHR's own text
under BUSL-1.1, written for submission to openEHR; nothing here has been
submitted.

## The layout it follows

- `openEHR/antora-openehr` at commit
  `99f995023d11a2d55a80ae054c977375f5f54ddb` (2026-11-06), read for its
  `MIGRATION-GUIDE.md`: one Antora module per specification, pages under
  `modules/<module>/pages/`, `module_vars.adoc` and `amendment_record.adoc`
  as module partials, class partials flat under
  `modules/ROOT/partials/classes/`, cross-component references as
  `component:module:page.adoc`.
- `openEHR/specifications-RM`, branch `development`, at commit
  `448aad4ee5024df24dc05a080749682af3972898` (2026-11-06), the RM component
  as that toolchain migrated it, read for the conventions of an existing
  module: `ehr_extract` (the index page with its header, Purpose, Related
  Documents and Feedback; a page per package with `== Class Descriptions`;
  the amendment record included from the appendix; `manifest.json` entries)
  and the ROOT class partials (`classes/`, `definitions/`, `BMMs/`).

Both were cloned into a scratch folder and read as data; nothing from them
was run, and nothing from them is copied here.

## How the tree maps onto `specifications-RM`

| Here | In `specifications-RM` |
|---|---|
| `modules/access_log/` | a new module `modules/access_log/` |
| `modules/ROOT/partials/classes/`, `definitions/`, `BMMs/` | new files in the same ROOT directories |
| `computable/BMM/openehr_access_log_0.1.0.bmm.json` | `computable/BMM/` beside `openehr_rm_1.2.0.bmm.json` |
| `manifest-entry.json` | one more entry in the `specifications` array of `manifest.json` |
| none | `modules/access_log/nav.adoc` added to the `nav` list of `antora.yml`, and a line in `modules/ROOT/pages/index.adoc` |

The pages `terminology.adoc`, `its_rest.adoc` and `aql.adoc` propose changes
to the TERM, ITS-REST and QUERY components; each says so in a note, and on
submission each moves to its own component.

## Generated parts

In `specifications-RM` the class partials are generated by
`ghcr.io/openehr/bmm-publisher` from the BMM. Here the `definitions/` and
`BMMs/` partials were rendered from
`computable/BMM/openehr_access_log_0.1.0.bmm.json` in the same table and
JSON form, and the `classes/` partials carry the Definition and BMM tabs
only. The Effective and UML tabs, the class SVGs under
`modules/ROOT/images/uml/` and the package diagram come from bmm-publisher
when the module enters the RM repository, and replace these partials.
