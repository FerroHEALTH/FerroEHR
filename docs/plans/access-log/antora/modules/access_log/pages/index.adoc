= {spec_title} [.spec-status.spec-status-development]#{spec_status}#

Model of the record an EHR system keeps of every access to EHR data: who accessed, on whose behalf, what, when, why, under which authorisation, with which outcome and through which channel. The log is kept beside the EHR, keyed by `ehr_id`, append-only and hash-chained, and readable by the subject of care.

NOTE: This is a draft change proposal prepared in the FerroEHR repository. It has not been submitted to openEHR and is not part of any RM release.

== Purpose

The openEHR Architecture Overview lists access logging among the measures every EHR deployment needs, and states that "currently openEHR does not specify models of such logs, but might do so in the future" (xref:BASE:architecture_overview:security.adoc[Security and Confidentiality], Security Policy). openEHR audits every change through `AUDIT_DETAILS` on each `CONTRIBUTION` and `VERSION`, and no read. This document defines the access log as an RM package, `org.openehr.rm.access_log`, with the rules for writing, chaining, retaining and reading it, so that any CDR can keep a log another CDR, a reviewer or the patient can read in openEHR terms.

The intended audience includes:

* Standards bodies producing health informatics standards;
* Solution vendors;
* Medical informaticians, privacy officers and security officers.
