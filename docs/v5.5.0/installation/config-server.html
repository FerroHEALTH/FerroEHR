[server]

The HTTP listener: the section every FerroHEALTH product shares (ferrohealth-server), so the keys and their behaviour are the same in each. It carries the stack every request passes through: the server’s request id, the request timeout, the body limit, the concurrency bound, compression, the request log, the health routes and the bounded drain on SIGTERM.

[server]
listen = "0.0.0.0:8080"
base_path = ""
request_timeout_ms = 30000
header_read_timeout_ms = 30000
body_limit_bytes = 67108864
drain_delay_ms = 0
shutdown_timeout_ms = 10000
# max_concurrent_requests = 256
retry_after_s = 1
trusted_proxies = []
forwarded_header = "forwarded"
compression = true
compression_min_bytes = 1024
KeyTypeDefaultDescription
listensocket address0.0.0.0:8080The IP address and port the listener binds: every interface at the port the container image exposes. A host name is refused at startup. PORT alone gives 0.0.0.0:<PORT>, and FERROEHR__SERVER__LISTEN wins over both. Set 127.0.0.1:8080 to keep a bare binary on the loopback.
base_pathstringemptyThe path every route is served under, the health routes included. Empty serves them at the process root. The openEHR API path is rest.base_path.
request_timeout_msint30000A request still running after this long is answered 408 with the openEHR error body.
header_read_timeout_msint30000How long a client may take to send its request head, once connected or after its last response; a client still sending then is disconnected. Bounds the slow-header connection, which no other limit reaches. 0 is refused.
body_limit_bytesint67108864 (64 MiB)The largest request body any route reads, refused 413 above it. The bulk routes (operational-template upload, /message/import) take up to this; rest.body_limit_bytes narrows the rest of the clinical surface below it. The largest operational template in the vendored CKM corpus is several megabytes, well below this ceiling.
drain_delay_msint0On SIGTERM or SIGINT, readiness answers 503 this long while the listener still accepts, so an orchestrator stops routing first.
shutdown_timeout_msint10000Then the listener closes and the requests in flight get this long to finish; a connection still open after it is dropped.
max_concurrent_requestsintunsetThe requests served at once. Past it a request is answered 503 with Retry-After and the openEHR error body, never queued, so offered load beyond capacity cannot exhaust memory. The health routes are never refused. Unset, there is no bound.
retry_after_sint1The Retry-After of a 503 or 429 the listener writes.
trusted_proxieslist[]The reverse proxies, as addresses or CIDR blocks, whose forwarded client address is believed. Empty, every request is named by its peer address.
forwarded_headerenum{forwarded,x-forwarded-for}forwardedThe header a trusted proxy names the client in (Forwarded is RFC 7239).
compressionbooltrueCompress a response with gzip or Brotli when the client accepts one.
compression_min_bytesint1024The smallest response body that is compressed.

A refusal the listener writes itself (408, 413, 429, 503) and a handler that panics (500) answer the standard openEHR { error, message } body. 413 and 429 are not in the ITS-REST status table; ITS-REST admits them as additional, non-conflicting codes, and they are what RFC 9110 §15.5.14 and RFC 6585 §4 define for these refusals. A panic’s message reaches neither the body nor the log.

Every request gets a request id the server mints, which the request log and the access record carry and the response returns in X-Request-Id. A client’s own X-Request-Id is returned to it unchanged and never recorded.

[server.caller_rate]: per-caller request rates

[server.caller_rate]
requests_per_second = 1024
burst = 2048
KeyTypeDefaultDescription
requests_per_secondint(required in the table)Sustained requests per second one authenticated subject may send on the clinical API.
burstint(required in the table)How many requests one subject may send at once before the rate applies.

Unset, no caller is limited. The chart and the Compose quickstart set the values above.

This is not max_concurrent_requests, and you can tell them apart from the status alone. max_concurrent_requests protects capacity: too many requests in flight at once, from anyone, and the excess is refused 503 + Retry-After. The caller rate protects fairness: one caller asking too often over time, refused 429 + Retry-After. A 503 means the server is full; a 429 means you are asking too fast.

The limit is keyed on the authenticated subject, the only fair key for a clinical API: a hospital behind one NAT is a single address. It sits inside authentication, so the health routes, the status document and the discovery document are never refused by it.

Tip

Benchmarking this server? Lift the caller rate first, or you will measure it instead of the server. The project’s own measurement lanes compose an overlay that does exactly that, and both instruments refuse to write a record if the server answered any 429.

[server.tls]: native TLS and mutual-TLS client authentication

Native TLS termination on the main listener, unset by default; deployments commonly terminate TLS at an ingress. client_auth = "required" is the IHE ATNA ITI-19 mutually-authenticated-node posture (see the Audit trail chapter). The separate-port management listener always stays plain HTTP, so under deployment_profile = "production" setting [management] port opens the plaintext_listener gap.

[server.tls]
certificate_file = "/etc/ferroehr/server.pem"
key_file = "/etc/ferroehr/server.key"
client_auth = "none"
min_version = "1.3"
# reload_interval_s = 60
KeyTypeDefaultDescription
certificate_filepath(required in the table)Server certificate chain (PEM), the leaf first. A missing, unreadable or certificate-less file stops startup.
key_filepath(required in the table)Server private key (PEM), read as a secret file. A key that does not belong to the leaf stops startup.
client_authenum{none,optional,required}noneClient-certificate policy. optional verifies a certificate when one is presented and still accepts connections without; required rejects any client without a verified certificate at the handshake.
client_ca_filepathunsetThe explicit CA bundle client certificates must chain to, never the web PKI. Required unless client_auth = "none".
min_versionenum{“1.3”,“1.2”}"1.3"The lowest TLS version this listener negotiates. "1.0" and "1.1" are refused when the configuration is read (RFC 8996).
reload_interval_sintunsetHow often the certificate, key and client CA are read again while the server runs. The files are always read again on SIGHUP. A changed pair is served, and a changed client CA verifies, from the next handshake on without a restart; a read that fails is logged and the running configuration stays.
healthcheck_identity_filepathunsetThe client certificate chain and key, in one PEM, that ferroehr healthcheck presents to a listener requiring one.

ferroehr healthcheck speaks TLS to a TLS listener over the loopback and accepts exactly the leaf certificate in certificate_file.

Note

min_version defaults to 1.3 only, as RFC 9325 §3.1.1 has it supported. Setting "1.2" enables 1.2 alongside 1.3, with the four forward-secret suites RFC 9325 §4.2 recommends; pick it only for a client that cannot do 1.3, such as an older integration engine or a pinned Java runtime.

Note

An EC certificate must name its curve. RFC 5480 §2.1.1 forbids explicit curve parameters, TLS clients refuse such a certificate, and the server refuses the pair at startup. LibreSSL (the openssl that ships with macOS) writes explicit parameters from genpkey and req -newkey ec unless you add -pkeyopt ec_param_enc:named_curve; openssl ecparam -name prime256v1 -genkey writes a named curve.

base_path: shortening the REST base path

ITS-REST leaves the API base to the deployment and fixes only the version segment at its end, so you may shorten base_path. The shape is checked at boot, and a value that breaks a rule stops the server with an error naming the key and every rule it broke:

  • The first segment is ferroehr. /ferroehrx/v1 and /x/ferroehr/v1 are refused. This segment is not configurable away.
  • The last segment is v1, the openEHR API version this server implements. The shortest accepted value is therefore /ferroehr/v1.
  • No trailing slash, no empty segment (//), and every segment uses only the unreserved URL characters A-Z a-z 0-9 - . _ ~.

The status and documentation routes hang off the REST root, which the server derives from base_path by dropping the segments that name the openEHR API: the trailing v1, plus an openehr segment directly before it when you spell one.

base_pathREST rootStatus document
/ferroehr/rest/openehr/v1 (default)/ferroehr/rest/ferroehr/rest/status
/ferroehr/openehr/v1/ferroehr/ferroehr/status
/ferroehr/v1/ferroehr/ferroehr/status
/ferroehr/cdr/v1/ferroehr/cdr/ferroehr/cdr/status

The Swagger UI ({rest root}/swagger-ui), the OpenAPI documents ({rest root}/api-docs/…) and the SMART discovery document ({rest root}/.well-known/smart-configuration) move with it. The health family is served under server.base_path, which is empty by default, so it stays at the process root: /health, /health/liveness, /health/readiness.

Set it from the environment with:

FERROEHR__REST__BASE_PATH=/ferroehr/v1

Note

The ferroehr healthcheck subcommand, which the published container images run as their Docker health check, asks GET /health/readiness on the server.listen port over the loopback, so rest.base_path does not move it.

Behind a path-prefixed reverse proxy

A proxy that mounts the CDR under a prefix stacks that prefix on top of base_path. A proxy serving the server at /cdr with the default base path gives clients URLs like:

https://cdr.example.org/cdr/ferroehr/rest/openehr/v1/definition/template/adl1.4

Two ways to shorten that. Strip the prefix at the proxy, so the server sees the path it serves (nginx proxy_pass http://cdr:8080/; with the trailing slash, Caddy handle_path, Traefik StripPrefix). Or shorten the base path:

FERROEHR__REST__BASE_PATH=/ferroehr/v1

which gives https://cdr.example.org/cdr/ferroehr/v1/definition/template/adl1.4.

Whichever you choose, tell every client. The server builds its Location headers, its served OpenAPI paths and its SMART discovery document from its own rest.base_path, and it cannot see a prefix the proxy adds. The FerroEHR Viewer has its own mirror key, cdr.base_path, which must match.

system_id: the data-authoring identity

system_id is the identifier this CDR stamps into the data it authors. It appears on the wire in three places:

  • EHR.system_id, recorded when an EHR is created. The openEHR RM (EHR Information Model, EHR Identifier Allocation) says the EHR.system_id “should be set to the value that would normally be used for locally created EHRs”: a value the deployment chooses, not a product constant.
  • AUDIT_DETAILS.system_id on every commit for which the client did not supply one through the openehr-audit-details header. The openEHR REST API requires that “when system_id is not provided by the client, the server MUST set it to its own configured system identifier”.
  • OBJECT_VERSION_ID.creating_system_id: the middle segment of every version identifier the server mints (<object_id>::<creating_system_id>::<version>).

Practical notes:

  • The value must be a legal openEHR UID: a UUID, an ISO OID, or an internet id (a reverse-domain / DNS-style name) per the openEHR BASE identification grammar. The server judges it with the same validating constructor its reader uses and refuses to boot on an illegal value, because it becomes the creating_system_id segment of every version identifier the server mints and an illegal value would produce ids the server’s own reader rejects. A DNS-style name like cdr.hospital.example is valid; an empty value, or one containing the :: field separator, is not.
  • Choose it before going live and keep it stable. The value is stored with each EHR and each version; changing it later affects only newly authored data: existing EHR ids, audit rows and version identifiers are never rewritten, and previously issued OBJECT_VERSION_IDs stay valid.
  • Make it unique per system, so data exchanged between openEHR systems keeps unambiguous provenance. A node of a federation must hold a system_id no other member uses (Federation Tier N42a); the default ferroehr.local is the same on every node that leaves it unset. See FerroEHR as a federation node.
  • system_id is not [rest.identity]. system_id says which system authored the data; [rest.identity] is the display identity of the OPTIONS System-Options manifest. Rebranding changes the manifest and nothing in stored data; changing system_id changes what new data says about its origin and leaves the manifest alone.

PostgreSQL connection.

Credentials are redacted from every rendering. DATABASE_URL is a recognized lower-priority alias.

migrate_urlsecret URLunsetDSN that PREPARES the schema, used for that one boot step and then closed. It prepares every domain whose DSN reaches the SAME DATABASE — which is the whole of the separated-credential posture, where each domain has a login role of its own on one database; a domain whose DSN reaches a different database is prepared on that database’s storage.migrate.<domain>.url (on the domain’s own DSN when that is unset). Which it is, is read from the server (pg_control_system() plus current_database()), never from the DSN text. Unset, it falls back to url. See Operations → Which credential prepares the schema.
migrate_url_filepathunsetRead migrate_url from a file instead, for a mounted secret. At most one of the pair.

That check still READS every _sqlx_migrations table of each database, which no least-privilege role can do, so pair it with migrate_url above and with ferroehr db migrate run out of band; see Operations.

min_connectionsint2Idle connections kept open, avoiding cold-reopen churn under variable load.
acquire_timeout_secsint30Seconds to wait for a free connection before failing.

statement_timeout_ms is the backstop the HTTP request timeout cannot be: answering a client by dropping the handler future does not cancel the statement PostgreSQL is running, so without it a handful of expensive queries can hold every pooled connection while every one of their callers has already given up. Keep it above query.timeout_ms so the AQL engine’s own typed refusal fires first and this only catches what the engine does not govern.

[storage]

One DSN per storage domain. Every domain always lives in its own schema (clinical, party, linkage, audit) and every pool carries only its own on its search_path, so no statement can reach another domain’s relations without naming a schema it is not granted. Setting a url here adds the CREDENTIAL separation, and — if the DSN names another host — lets the domain live in a database or cluster of its own.

[storage.party]
url_file = "/run/secrets/db-party-dsn"

[storage.linkage]
url_file = "/run/secrets/db-linkage-dsn"
KeyTypeDefaultDescription
storage.clinical.urlsecret URLunsetDSN the clinical domain connects on (role ferroehr_clinical). Unset, it uses db.url.
storage.party.urlsecret URLunsetDSN the party (demographic) domain connects on (role ferroehr_party). Unset, it uses db.url.
storage.linkage.urlsecret URLunsetDSN the linkage domain connects on (role ferroehr_linkage) — the map from a party to the EHR whose subject it is, barred from both domains it joins and they from it. Unset, it uses db.url.
storage.audit.urlsecret URLunsetDSN the audit repository is written through. Unset, it uses db.url.
storage.<domain>.url_filepathunsetRead that domain’s DSN from a file instead, for a mounted secret. At most one of the pair.

Why a schema is not always enough: a base backup, WAL archiving and physical replication carry every schema of a database together (PostgreSQL 18, Backup and Restore), so a separation that must survive those is a separation of databases. The Swiss EPDV Art. 10 Abs. 1 lit. b asks for storage “von anderen Datenbeständen getrennt” and the DSV Art. 4 Abs. 5 for the log to be kept “getrennt vom System, in welchem die Personendaten bearbeitet werden”; openEHR reads the same way for the identity cross-reference, which “could be located on different machines” (BASE architecture_overview/master07-security.adoc §Anonymity). No openEHR spec governs pools or database roles — this is our own design.

What the server checks at boot:

  • a runtime role that can read another domain’s relations is refused, always;
  • two domains configured on different DSNs that turn out to authenticate as the same database role are refused — a separation that exists only in the configuration is worse than none, because it reads as one that holds;
  • a missing domain role is a warning under deployment_profile = "sandbox" and a refusal under production, where there are no grants to separate anything with.

Each database is prepared on its own migration credential. [db] migrate_url names one database; a domain whose DSN reaches another database is prepared there, and verified there under migrate = "verify", on the credential named in [storage.migrate.<domain>]:

[storage.linkage]
url_file = "/run/secrets/db-linkage-dsn"           # postgres://ferroehr_linkage:…@linkage-db/…
[storage.migrate.linkage]
url_file = "/run/secrets/db-linkage-migrate-dsn"   # postgres://ferroehr_migrator:…@linkage-db/…
KeyTypeDefaultDescription
storage.migrate.<domain>.urlsecret URLunsetDSN that prepares the database the domain lives in, when that is not the database db.migrate_url reaches. Used for that one step and closed again. Unset, such a database is prepared on the domain’s own url, which a DML-only runtime role cannot do: it is refused on the first bookkeeping table it cannot read.
storage.migrate.<domain>.url_filepathunsetRead it from a file instead, for a mounted secret. At most one of the pair.

The server refuses to start when a domain’s url and its storage.migrate URL reach different databases. A database that holds the linkage domain without the party domain also receives the party migration set, its schema and grants and never a row, because the linkage set revokes a function the party set creates.

The request log writes one line per request: the method, the matched route template, the status, the latency and the server’s request id, never a body, the raw path or a header value. Tip

The ASCII boot banner follows the rendering that is actually installed, not the configured word: it prints for pretty, and for auto only when stdout is a terminal. Under json, and under auto off a terminal (a container, a pipe into a log collector) stdout is parseable JSON from the first byte.

Note

Instrument names carry no Prometheus suffix; the exporter derives one. A counter named auth_failures is scraped as auth_failures_total, and units add _seconds/_bytes. Over OTLP the unsuffixed name is what a collector receives.

The scrape endpoint itself is not opened here; it is management.endpoints.prometheus, which is off until you name a level.
